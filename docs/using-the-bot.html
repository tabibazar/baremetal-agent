A guide to @unikernel_bot

Talking to a Unikernel

There is a Telegram bot whose replies come from a program with no operating system underneath it. No kernel, no shell, no container, no disk — 2.9 MB of machine in 16 MiB of RAM. Here is everything it can do, with real transcripts.

Message @unikernel_bot on Telegram

Send /start. That first reply is written in C, not by the model — it is the one answer the machine gives without asking anything.

What you are actually talking to

Most bots are a program, inside a runtime, inside a container, inside a Linux VM, on a host. This one is a single compiled binary that is the machine. It is loaded by the hypervisor and execution begins in its own main(). There is nothing else running — no process to restart, no shell to log into, no filesystem to write to.

That is why almost every question about itself has a real answer. It is not describing a machine from the outside; it is the machine, and it measures itself when you ask.

Ask it about itself

This is what it is best at. Every number comes from a measurement taken at the moment you ask — the system prompt forbids estimating, rounding into a nicer figure, or recalling a number from training.

What are you running on?
used machine_facts
I'm running on a bare-metal unikernel under Firecracker, with 16 MiB of RAM. The image itself is the entire machine, so there's nothing else installed or running. I've been up for 1 second.
How much memory are you using right now?
used memory_usage
I am currently using 9.8MB of static memory. My arena usage is 25.5KB right now, with a peak of 25.6KB in this conversation and 25.7KB since I last booted. I also have 8.3MB allocated for the semantic index, 262.1KB for HTTP buffers, and 131.1KB for payload buffers. This means I'm using about 58.5% of the machine's total RAM.
What is inside your image?
used build_info
I have musl libc, lwIP (TCP/IP), mbedTLS (TLS 1.3), libcurl (HTTP), cJSON, and the Mozilla CA bundle linked in. I do not have an operating system, kernel, init, shell, package manager, container runtime, or language runtime. I am running the gemini-2.5-flash model.
How quickly did you start up?
used startup_timing
I started up in 85.9 milliseconds. This includes the process start, network bring-up, DNS, TCP connect, TLS handshake, and the first HTTP response. It excludes the virtual machine booting before the program began.

Also worth asking: “how fast is your connection?” (it opens a real HTTPS connection and times the handshake), and “how many people have talked to you?” (counted across every restart, not just this one).

Try to catch it out

Ask something it cannot measure — “how many CPU cores could you have?”, “what does this cost to run?” — and it should tell you it does not know rather than guess. If it ever gives you a number about itself that it could not have measured, that is a bug worth reporting.

Tell it things, and ask later in different words

The machine has no disk. Anything it keeps lives on another machine, a network round-trip away — and it survives restarts, of which there have been dozens.

Remember that I take my coffee black, no sugar.
used remember
I've made a note that you take your coffee black, no sugar.

The interesting part is getting it back. It keeps a semantic index in its own RAM — every note embedded as a 768-dimension vector in a static array — so it finds things by meaning rather than by the words you happened to use:

What did I say about how I like my espresso?
used recall_similar — “espresso” was never in the note
You like your coffee black, no sugar.

There are two ways to get memories back and it picks between them. recall returns your most recent notes in order, for “what do you know about me?”. recall_similar searches all of them by meaning — one pass over the array, no database, no disk, about 47 microseconds across thirty notes.

It keeps the last 100 things per person and forgets the oldest beyond that. Notes are strictly per-conversation: every vector carries the chat it came from, and a search cannot cross between them. Your notes are not readable by anyone else talking to the same bot, however they ask.

Ask it to remind you

Reminders are delivered even if the machine restarts in between — they live in the same off-machine store the notes do.

Remind me in 3 hours to call the plumber.
used remind_me with in_seconds: 10800
I've set a reminder for you in 3 hours to call the plumber.
What reminders do I have?
used list_reminders
You have a reminder set to "call the plumber" in approximately 3 hours.

Say it however you like — “tomorrow morning”, “in 20 minutes”, “next Friday”. It works out the delay itself. Anything from 20 seconds to 90 days ahead, up to 20 pending at a time.

Why it asks for a delay and not a date

An earlier version asked the model for an absolute Unix timestamp. It failed about half the time with an empty reply, and when it did answer it sometimes produced a timestamp from December 2023 — recalled from training rather than computed. Switching to “how many seconds from now” took it to five clean runs out of five. The clock arithmetic belongs in C.

Ask about the outside world

It can search the web and read pages. It keeps the two kinds of knowledge visibly apart: things about itself are measured here and now, things from the web are somebody else's claim, and it tells you which it is giving you.

What is MirageOS and who maintains it?
used web_search
MirageOS is a library operating system that allows you to construct secure, specialised unikernels. It is an open-source project created and maintained by the MirageOS Core Team.

If a search snippet is too thin, it will fetch the page itself and read the whole thing. But it can only open a page whose host appeared in a search result it just ran — it cannot be talked into fetching an arbitrary URL you hand it. That guard is in the C, not in the prompt, because a prompt can be argued with.

Web answers are only as good as the search

Treat anything it read online the way you would treat a search result, not the way you would treat its measurements of itself. In testing it confidently reported a Formula 1 result that was almost certainly stale. It is honest about where a claim came from; it cannot vouch for the claim.

Things it genuinely cannot do

  • Write a file. There is no writable filesystem — open(O_CREAT) fails, verified. Everything it keeps goes over the network.
  • Remember an image, voice note or document. It reads text messages only.
  • Keep its index across a restart. The vectors live in RAM and die with it. Your notes survive, and the first topical search after a restart rebuilds the index from them — that one takes a few seconds longer.
  • Reliably decide to search its own memory. Roughly three times in four it searches before saying it does not know something about you. If you get a “don't know” that feels wrong, ask again more specifically — the note is usually there.

If you want to run your own

The whole thing is about 1,900 lines of C, MIT licensed, with no heap: cJSON is pointed at a static bump arena and the allocator is compiled out, so a future edit cannot quietly reintroduce one.

git clone https://github.com/tabibazar/baremetal-agent
# then follow README.md — you need a Linux x86-64 host,
# a Telegram bot token, and a model API key.
make            # builds for Linux/macOS, same source as the unikernel

It runs unchanged as an ordinary process on Linux and macOS, which is how it is developed; the unikernel build is a different link, not different code. ./bmagent --ask "..." answers one question in your terminal without Telegram involved, which is the fastest way to see it work.

Every exchange on this page is a real one, captured from the agent against its live store — none are written by hand. Figures are from the running instance and will drift as it is used.
